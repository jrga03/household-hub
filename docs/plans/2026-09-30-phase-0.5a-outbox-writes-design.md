# Phase 0.5a: Transaction, Account, and Category Writes Through the Outbox (Design)

**Date:** 2026-09-30
**Roadmap:** `docs/plans/2026-09-30-guardrails-roadmap.md` (Phase 0.5)
**Branch:** `phase-0.5a-outbox-writes`

## Goal

Every transaction, account, and category write goes through `src/lib/offline/*`, so it works offline and lands in the sync queue. After this phase the only direct Supabase writes left in `src/lib/supabaseQueries.ts` are the budget hooks, which Phase 0.5b handles.

## Background (verified 2026-09-30)

- `supabaseQueries.ts` has 15 direct `.insert/.update/.upsert/.delete` calls. Eleven are in scope here; four are budget writes (0.5b).
- IndexedDB is not a full mirror. The reconnection catch-up (`src/lib/realtime-sync.ts` `fetchLatestChanges`) pulls rows changed since a cursor, and a fresh device starts with the last 24 hours. Offline mutations read the existing row from IndexedDB (`transactions.ts:171`, `:282`, `accounts.ts:185`, `categories.ts:196`), so older rows fail with "not found". `TransactionFormDialog.tsx:243-258` works around this with a direct Supabase write.
- `createOfflineAccount`, `updateOfflineAccount`, `deactivateOfflineAccount`, and the three category equivalents have no callers and no tests.
- `createOfflineAccount`/`updateOfflineAccount` map `'e-wallet'` to `'cash'`, and `createOfflineAccount` hardcodes `sort_order: 0`.
- Type drift: the server allows account type `'e-wallet'` (`supabase/migrations/20251023224854_create_accounts.sql:15`) and `AccountInput` includes it, but `LocalAccount.type` (`src/lib/dexie/db.ts:66`) does not. `AccountFormDialog` sends `sort_order` and `owner_user_id`, which `AccountInput` lacks.

## 1. Fetch on miss

New `src/lib/offline/ensureLocal.ts`:

```ts
export async function ensureLocalRow(
  table: "transactions" | "accounts" | "categories",
  id: string
): Promise<LocalRow | null>;
```

Returns the IndexedDB row when present. Otherwise it selects that one row from Supabase by `id`, `put`s it into IndexedDB, and returns it. A failed fetch or a missing row returns `null`, and the caller keeps its existing "not found" result. `updateOfflineTransaction`, `deleteOfflineTransaction`, `updateOfflineAccount`, and `updateOfflineCategory` use it in place of their bare `db.<table>.get(id)`; the `deactivate*` functions inherit it if they delegate to `update*`, otherwise they call it directly.

This is a Supabase read, so it does not break the outbox rule. Offline, the UI reads only from IndexedDB (`src/lib/offline/reads.ts`), so a row the user can act on while offline is already local; a missing row only occurs online, where the fetch can succeed.

## 2. Shared enqueue-then-drain step

New `src/lib/offline/afterWrite.ts`:

```ts
export function afterOutboxWrite(
  queryClient: QueryClient,
  userId: string,
  queryKeys: QueryKey[]
): void;
```

Invalidates `queryKeys` immediately; when `navigator.onLine`, fire-and-forgets `syncProcessor.processQueue(userId)` and invalidates `queryKeys` again when it settles, swallowing errors so a failed drain is never an unhandled rejection. `processQueue` already collapses concurrent calls into one run (`processingPromise`).

`useCreateTransfer` (`src/hooks/useTransfers.ts`) and `TransactionFormDialog` (`:306-315`) switch to it, so the step exists once.

## 3. Hook rewiring

| Hook (`supabaseQueries.ts`)                                       | New implementation                                         |
| ----------------------------------------------------------------- | ---------------------------------------------------------- |
| `useCreateAccount`                                                | `createOfflineAccount`                                     |
| `useUpdateAccount`                                                | `updateOfflineAccount`                                     |
| `useCreateCategory`                                               | `createOfflineCategory`                                    |
| `useUpdateCategory`                                               | `updateOfflineCategory`                                    |
| `useUpdateTransaction`                                            | `updateOfflineTransaction`                                 |
| `useToggleTransactionStatus`                                      | `updateOfflineTransaction` with the flipped status         |
| `useDeleteTransaction`                                            | `deleteOfflineTransaction`                                 |
| `useSetTransactionStatus`                                         | new `updateOfflineTransactionsStatus(ids, status, userId)` |
| `useArchiveAccount`, `useArchiveCategory`, `useCreateTransaction` | deleted (no callers)                                       |

Each `mutationFn` throws `new Error(result.error ?? "<fallback>")` on `success: false`, as `useCreateTransfer` does, and each `onSuccess` calls `afterOutboxWrite` with the hook's current invalidation keys. Hook signatures seen by components stay the same except where an argument is only needed by the old Supabase call; the userId comes from `useAuthStore` inside the hook.

`updateOfflineTransactionsStatus` writes every updated row and every queue item in one Dexie `rw` transaction (built before the transaction opens, like `createOfflineTransactionsBatch`), using `ensureLocalRow` for each id first. A bulk status change is all-or-nothing locally.

`TransactionFormDialog`'s fallback to `updateTransaction.mutateAsync` (`:243-258`) is deleted; with fetch on miss, `updateOfflineTransaction` succeeds for server-only rows. A remaining failure surfaces as an error toast.

## 4. Offline account and category functions

- Add `src/lib/offline/accounts.test.ts` and `categories.test.ts`: create, update, and deactivate each write the row and exactly one queue item of the right entity type and op; update on a row missing locally uses fetch on miss (Supabase select mocked); update on a row missing everywhere returns `success: false` and writes nothing.
- Add `'e-wallet'` to `LocalAccount.type`, and delete the `e-wallet → cash` mapping in `createOfflineAccount` (`accounts.ts:101`) and `updateOfflineAccount`. The server accepts `'e-wallet'` (`create_accounts.sql:15`); the mapping would silently store e-wallets as cash once the form uses these functions.
- `AccountInput` gains optional `sort_order` (used by `createOfflineAccount` instead of the hardcoded `0`, defaulting to `0`) and `is_active` becomes optional (default `true`). `owner_user_id` stays derived from visibility and the user id, as today; the form's `owner_user_id` field is not passed through.
- `CategoryInput`: `is_active` and `sort_order` become optional (defaults `true` and `0`). `CategoryFormDialog` sends `{ name, parent_id, color, icon, sort_order }`, which then fits without casts.

## Decisions & Deferrals

- **Fetch on miss, not a full local copy (decided 2026-09-30).** Why: keeps 0.5a focused; a full backfill is its own feature. Revisit: roadmap "Future: full local copy".
- **Budgets split into Phase 0.5b (decided 2026-09-30).** Why: the local budget mirror replaces a month's rows on every online fetch (`mirrorBudgetsForMonth`), which would drop unsynced writes, and `UNIQUE(household_id, category_id, month)` makes an outbox create fail terminally when the server already has that category/month (`processor.ts:278` only treats primary-key duplicates as success). Revisit: 0.5b spec.
- **Unused write hooks are deleted, not migrated.** Why: no callers; deletion clears their violations with no behaviour change. Revisit: never.
- **Bulk status update is one Dexie transaction.** Why: a per-row loop could leave a partial selection updated if one row fails. Revisit: never.
- **`test-import.csv` deleted; archived Phase A doc untouched.** Why: the spec that used it is gone; the archive records history. Revisit: never.
