# UI overhaul

Status: scoped 2026-10-13 in a grilling session. Runs before #99 (drafts and review), which then builds onto the Review screen. Spec: #106. Folds in #102.

## Context

- The create-or-join screen ignores the safe area, so it collides with the Dynamic Island, and stacks both forms at once.
- Home mixes finances with household admin and account management.
- Transactions shows filters, totals, a needs-category link, an always-visible select row, and a status badge plus trash icon on every row.
- Forms are centered dialogs with no keyboard handling (no `visualViewport`, `interactive-widget` or `enterKeyHint`).
- Every route draws its own title and description block, while the phone header always says "Household Hub".
- The Categories screen combines defining categories, allocating money and tracking spend in one view, with `/distribute` on the side.
- The phone drawer puts the email above the links.

The app is used mostly on phones; desktop must stay good but gets no separate layout for now.

## Decisions & Deferrals

- **One plan, seven issues.** #107 shipped on its own (PR #115). Changed 2026-10-13: the remaining six are built together with `/implement-spec` on the integration branch `feat/106-ui-overhaul` (parallel worktree agents along the blocked-by graph, one PR closing all of them), not one per session. Why: the user chose it. Revisit: never.
- **#99 shipped before the overhaul** (PR #113, drafts reviewed on `/import`). So #110's Review screen gets an "Imported drafts" section that shows the draft count and links to `/import`; it doesn't move the draft review UI. Confirmed by the user 2026-10-13. Revisit: if reviewing drafts inline on `/review` is wanted.
- **#102 is folded in** as the Accounts + Household issue. Accounts get `/accounts` (the current card, moved); tapping an account opens Transactions filtered to it. Revisit: never.
- **Deferred: the per-account register.** Revisit: unchanged from the re-architecture plan.
- **Phone nav: bottom tabs are Home and Transactions, plus the existing FAB.** The drawer holds Budget, Review, Accounts, Import, Categories, Settings, with email and sign out pinned at the very bottom. The desktop sidebar uses the same items as a daily group and a manage group. Why: keep the tab bar small for now. Revisit: if Budget or Review proves to be a daily destination.
- **The header shows the page title**: the household name on Home, the page name elsewhere. It has a back arrow on pushed screens, a right-side actions slot (month picker, Edit plan, Select) and the sync icon. In-page title and description blocks are removed; descriptions survive only in empty states. The "HH" badge and "Household Hub" text remain only in the drawer header.
- **Home is finances-only for now**: Review banner (when items exist), opening checklist, This month, Budgets, Balances, Latest. Household (name, code), Join requests and Members move to Settings → Household. Balances link to the account on `/accounts`. Revisit: when non-finance sections (todos) arrive.
- **Review is its own route** (`/review`): uncategorized expenses, imported drafts (#99, later) and owner-only join requests. Each section hides when empty, and the page shows an all-clear state at zero. The count is the sum of all sections. It shows on the drawer entry, as a dot on the hamburger and in the Home banner.
- **Transactions is filters + list only.** The Totals block and the needs-category link are removed (that link moves to Review). Filters stay collapsed behind one button on phones.
- **Rows sit under sticky date headers** (Today, Yesterday, Mon Oct 12). Line 1 is description and signed, colored amount; line 2 is category · account, muted; transfers get an icon. Rows have no checkbox, trash icon or status badge.
- **Pending rows are muted, with a Lucide `Info` icon before the amount** (accessible label "Pending"). There is no background color, because color alone fails WCAG 1.4.1. Warning icons are reserved for Review-type problems. Cleared rows look normal.
- **Status stays.** Swipe right _reveals_ "Mark cleared/pending" and swipe left _reveals_ "Remove"; both need a tap. The row snaps back on scroll or on a tap elsewhere. Bulk "Mark" buttons are removed.
- **Remove asks for confirmation** ("Remove 'Lunch' ₱250?"; bulk shows the count), and the existing undo toast is kept.
- **Selection mode**: entered by long-press or a header "Select" button. The header becomes "N selected ✕", and a bottom action bar (Category, Remove) replaces the tab bar and FAB. On desktop the bar sits at the bottom of the list column.
- **Description is required** for new and edited transactions, enforced in the command, never the decoder. Old events with empty descriptions still decode and show the amount as their label until edited. Imports keep the statement description. Transfers stay optional with an auto label ("Transfer to BPI").
- **Budget splits into three screens.** Categories (setup) defines groups and categories, with no money figures and Suggested categories shown when empty. Budget (view-only) shows allocated / spent / left per category with a progress bar and group totals; it has a month picker in the header and a ledger drill-in (sheet on phones, right pane on desktop). Plan (set budget) is reached from Budget's "Edit plan" action and holds the "₱X to assign" bar with Distribute folded in, an amount input per category with last-month and this-month spent as hints, and Move money. `/distribute` is removed. Why: you check the budget often and plan it rarely; each screen does one job.
- **Overspending**: "left" shows as a negative red figure with a full red bar, and group headers total the same way.
- **Deferred: drag-reordering categories.** Revisit: if ordering by hand is missed.
- **Phone forms become bottom sheets** (shadcn Drawer/vaul) that stay above the keyboard (`interactive-widget=resizes-content`, plus a `visualViewport` fallback for iOS). The submit button is pinned above the keyboard, `enterKeyHint` is "next"/"done" and Enter advances fields. Desktop keeps centered dialogs and the Transactions edit pane. Revisit: if sheets prove cramped for long forms.
- **Onboarding**: safe-area padding, a compact brand mark, a Create / Join segmented toggle showing one form at a time, and "Signed in as … · Sign out" pinned at the bottom.
- **Desktop gets the same flows in wider layouts.** Revisit: if a separate desktop layout is needed.
- **Nav slots for routes that don't exist yet** (#107): `src/components/layout/nav.ts` holds Import, Categories, Settings today; Budget and Review join the daily group (#111, #110) and Accounts leads the manage group (#102). Revisit: as each route lands.
- **Done: the review dot on the tablet sidebar trigger** (#110): the tablet header's sidebar toggle carries the dot and names the count; the collapsed sidebar shows a dot on the Review icon, the expanded one a count badge. Revisit: never.
- **Re-deferred: an index for the review count** (#110). `countLocalReviewItems` still scans `db.transactions` for uncategorized expenses; drafts use `db.drafts.count()` and join requests come from the server. IndexedDB doesn't index null keys, so an index needs a projected "needs category" field and a Dexie version bump. Revisit: if it shows up against the performance budget.
- **Dropped: the Import page's privacy line** ("the file and its password never leave it"), removed with the in-page descriptions (#107). Why: not needed as a field hint either. Revisit: never.
- **Done: the "Review" glossary term** (#110): the list of uncategorized expenses, open drafts and (owner only) join requests, and its count. Revisit: never.
- **Deferred: rewriting `src/components/layout/README.md`**, which still describes an older nav (Budgets, Analytics, Transfers); #107 fixed only the lines it made false. Revisit: a separate docs cleanup.
- **The HH badge stays in the desktop sidebar header**, which plays the drawer's role on wide screens (#107). Revisit: never.
- **Balances deep-link to the account's row** (#102, confirmed by the user): `/accounts#account-<id>`, scrolled into view once accounts load (`useScrollToHash`, shared with Settings). Revisit: if the per-account register lands.
- **Settings lists Household first**, before Appearance and Export, and Accounts gets the "g a" shortcut (#102, confirmed by the user). Revisit: never.
- **`/accounts` drops the card's in-page title and description** (#102, confirmed by the user), keeping the "No accounts yet" empty state; done after merging #108, which rewrote the same card's forms. Revisit: never.
- **Household settings live in `src/components/households/HouseholdSettings.tsx`** (#102), a new file rather than a `git mv` of `src/routes/index.tsx`, which stays as Home. Revisit: never.
- **Each issue updates the e2e specs and layout baselines it breaks** (for example, the 16 specs that add accounts on Home and the checklist's `/#add-account` link). There is no separate test-migration issue.
- **`FormSheet` is the form container** (#108, `src/components/FormSheet.tsx`): `<FormSheet title description? onClose>` (mounted means open), `FormFooter` for the pinned buttons, and `advanceOnEnter` as the form's `ref`. #109 and #111 build their forms on it. Revisit: never.
- **Keyboard handling is ours, not vaul's** (#108): `repositionInputs` is off; on iOS `FormSheet` pads the sheet's bottom by the `visualViewport` inset (lifting it left a seam at its edge), and it scrolls the focused field into view on any visual-viewport height change. Why: vaul's repositioning resizes the sheet and fights the pinned footer. Revisit: if vaul's handling improves.
- **Enter keeps each device's usual behaviour** (#108, confirmed by the user 2026-10-13): on phones Enter moves to the next typed field (skipping pickers, a new line in Notes) and submits from the last one; on desktop dialogs and the Transactions edit pane Enter submits the form. `enterKeyHint` is set everywhere. Revisit: never.
- **`FormFooter` is pinned on desktop too** (#108, confirmed by the user 2026-10-13), in dialogs and the edit pane as well as phone sheets. Revisit: never.
- **Phone sheets close by X, swipe, tap outside, Escape or Back** (#108, confirmed by the user 2026-10-13). Swipe-down works on the handle and the body; a scrolled body only scrolls, and closes once back at the top (vaul's own rule). Revisit: never.
- **Deferred: a real-device check** of the keyboard and the swipe (#108). `tests/e2e/phone-sheets.spec.ts` emulates the keyboard (shrunk `visualViewport` for iOS, shrunk viewport for `resizes-content`) and swipes with CDP touches on Chromium but with mouse pointer events on WebKit, which has no touch-drag automation. Revisit: next time the app is tried on an iPhone and an Android phone.
- **Non-form sheets stay Radix `Sheet`** (#108, confirmed by the user 2026-10-13): the Categories ledger drill-in and the Import draft detail aren't forms. Revisit: #111 if the ledger sheet should drag like the form sheets.
- **Every transaction needs a description, imports included** (#109, confirmed by the user 2026-10-13): `addTransaction` and `editTransaction` refuse a blank one; the decoder is unchanged, so old events still decode and show their amount as the label. On `/import` a draft with a blank description reads "Needs a description", and Save stays disabled until every selected draft has one. A bulk category change still moves an old blank-description transaction, since it isn't editing the description. Revisit: never.
- **Modes live in the shell, not in Transactions** (#109, confirmed by the user 2026-10-13): `<ContextMode title exitLabel onExit>` (`src/components/layout/ContextMode.tsx`) titles the header with an ✕ (Escape and Back exit too, Back through `useHistoryBackClose` as sheets do) and, on phones, puts its actions where the tab bar and FAB were (`PhoneBottomChrome`), in the same footprint so `--bottom-chrome` holds. Wide screens render the actions where the mode is placed. Revisit: never.
- **Selection details** (#109, confirmed by the user 2026-10-13): the header shows "Select all"/"Select none" while selecting; a bulk action ends selecting; Import statement leaves the header on phones (it's in the drawer) and while selecting. Remove confirms in the app's AlertDialog on every width ("Remove “Lunch” ₱250.00?", "Remove 3 transactions?"). Revisit: if a phone drawer reads better for the confirmation.
- **Row details** (#109, confirmed by the user 2026-10-13): parentheses on the Transactions page and Home's Latest; minus elsewhere. Those two opt in to "(₱250.00)" (`expenseInParentheses` on `TransactionAmount`, built on `formatTransactionExpense` in `src/lib/currency.ts`); every other view keeps "−₱250.00". Both read as "minus ₱250.00" to screen readers, in the normal text colour; income is "+₱1,000.00" in green. A transfer without a description reads "Transfer to BPI", or "Transfer from BDO" when the list is filtered to the account it went into. Rows show a circle / circle-check only while selecting. The next date heading slides over the stuck one rather than pushing it. Revisit: never.
- **Deferred: a real-device check of swipe and long press** (#109); e2e drives them with CDP touches on Chromium only. Revisit: with #108's real-device check.
- **#112 tests the safe area by overriding `--safe-area-top/bottom`** (iPhone 15 Pro insets, 59px/34px) in `household.spec.ts`, since no desktop or emulated browser reports `env(safe-area-inset-*)`. Revisit: if a real-device check (BrowserStack or a physical iPhone) shows a mismatch.
- **#112 moved the Create / Join choices into `src/components/households/CreateOrJoin.tsx`** so the toggle and request states are unit-tested there; the route keeps only the page frame. Revisit: never.
- **Deferred: create-or-join opened offline shows no Create / Join choices** (they wait on the Join Request lookup, which pauses offline; same before #112). #112's offline e2e now waits for the form before going offline. Revisit: if someone reports a blank onboarding screen.
- **#112 onboarding details (confirmed by the user 2026-10-13):** the toggle opens on Create; Create is disabled while a Join Request is pending or declined (the server's `create_household` doesn't check open requests); the h1 "Welcome to Household Hub" stays but the intro paragraph is dropped; the cards under the toggle drop their "Create a household" / "Join a household" titles and keep their descriptions; the footer button keeps the app's "Sign Out" casing. Revisit: never.
- **Budget compares spending with the budget target** (#111, confirmed by the user 2026-10-13): each row shows budget (the target in force that month), spent (the month's spending less refunds, transfers excluded) and left = budget − spent. Overspent means spent > budget, the same `budgetStatus` Home's Budgets Over count uses: left shows negative in red with a full red bar. The bar is spent ÷ budget. A category without a budget shows its spent alone, with no bar and no left. A group's totals are exactly the sum of its visible rows, categories without a budget included, so a group can be overspent while none of its budgeted categories is. Retiring keeps history: a retired category gets its own row, labelled "Retired" and counted in its group's totals, in any month it had a budget in force or spending, and is absent otherwise; a retired group shows in a month when any of its categories does. Home's Budgets counts follow the same rule through `countsInMonth`, so the two agree. Plan amounts and Distribute still leave retired categories out (both also confirmed by the user 2026-10-13). The category's money shows on Plan only, as a "Holds" hint per row. Revisit: never.
- **Plan amounts save as you leave the field** (#111, confirmed by the user 2026-10-13), one `setBudget` per changed category from the Plan's month, keeping the funding account in force or taking the first that fits; emptying or 0 clears it. The row's "…" menu has Move money (into that category) and Budget details (the Set budget sheet, for the funding account and start month). Revisit: if a single Save button is wanted.
- **Distribute is a sheet on Plan** (#111, confirmed by the user 2026-10-13), opened by `/plan?distribute=income|opening` (with `account`, `amount`, `date`), so the payday toast and the opening checklist link straight to it. The checklist's "Set budgets" goes to Plan. Revisit: never.
- **Plan holds To assign, Move money, Pay card and the Allocations list** (#111, confirmed by the user 2026-10-13); each account's Unassigned folds under "By account". Budget's ledger rows still open their record (an allocation opens Edit allocation). Revisit: if allocation edits should leave the ledger.
- **Dropped: the per-category "by account" breakdown and the "Spent more than it holds" note** (#111, confirmed by the user 2026-10-13); the ledger names each record's account, and red plus a full bar marks overspending. Revisit: if the breakdown is missed.
- **Budget gets the "g b" shortcut** (#111). Revisit: never.
- **One review count, per kind** (#110): `REVIEW_KINDS` in `src/lib/review/count.ts` lists the kinds in section order; `useReviewCounts` (`src/hooks/useReviewCount.ts`) returns a count per kind and `useReviewCount` their sum, which the drawer badge, the hamburger dot, the tablet sidebar trigger, the sidebar entry and the Home banner read. A new kind adds to `REVIEW_KINDS`, `useReviewCounts` and the page's `SECTIONS` map (TypeScript asks for each); the consumers don't change. Confirmed by the user 2026-10-13. Revisit: never.
- **Join requests in the count offline** (#110): they count as the last list fetched this session, and as none after a reload while offline; the Review page then says "Join requests show when you're online" to the Owner. Uncategorized expenses and drafts are local and always counted. Why: requests are server-only and the query cache isn't persisted. Confirmed by the user 2026-10-13. Revisit: if owners miss requests while offline.
- **Review answers join requests in place** (#110): the section lists them with Accept and Decline (the same row as Settings → Household, which keeps its card), polling every 30 seconds while open. Confirmed by the user 2026-10-13. Revisit: if the owner would rather go to Settings.
- **Review sections link out, except join requests** (#110): uncategorized expenses show their count and "Categorize" to `/transactions?needsCategory=true`; imported drafts show their count and "Review drafts" to `/import`. Review gets "g r". Confirmed by the user 2026-10-13. Revisit: if listing the expenses inline is wanted.
