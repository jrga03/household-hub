# Debts UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** External debts can be created, viewed, paid and archived from the app, and the five cross-device debt gaps are closed before that becomes possible.

**Architecture:** Two branches. `debts-sync-gaps` adds one migration (server-owned timestamps, a nullable `ON DELETE SET NULL` transaction link, a unique reversal index, no server name uniqueness), teaches the processor that a duplicate reversal means "already reversed", and runs a deterministic ledger reconcile plus status re-derivation after every catch-up. The user deploys the migration to production. Then `debts-ui` adds `/debts` (layout route), `/debts/` and `/debts/$debtId`, built from thin route files over two testable page components that read Dexie through `xQueryOptions` builders, and removes the Knip ignore.

**Tech Stack:** Postgres/pgTAP (Supabase CLI 2.109.1), TypeScript, Dexie 4 (fake-indexeddb in vitest), TanStack Router/Query, React Hook Form, shadcn/ui, Playwright.

**Spec:** `docs/plans/2026-10-10-debts-ui-design.md` (approved 2026-10-10; revised at planning, see Decisions & Deferrals).

## Global Constraints

- Writes go through the outbox (`src/lib/debts/*`, `src/lib/offline/*`); only `src/lib/sync/` writes to Supabase. Lint enforces both.
- Ids are `crypto.randomUUID()`. Money is `Cents`; `asCents` only in `currency.ts` and `validations/**`. Parse `yyyy-MM-dd` with `parseLocalDate`, never `new Date("yyyy-MM-dd")`.
- No `any`, no `!` in production code, no blanket `eslint-disable` (each disable carries a reason).
- Query keys come from `src/lib/query-keys.ts`; each query is an `xQueryOptions()` builder next to its fetcher; every UI write calls `afterOutboxWrite(queryClient, userId, "<entity>")`.
- Every route uses `<PageShell variant="…">`. TanStack Router, Sonner toasts, `confirm()` from `@/lib/confirm`.
- External debts only. `CreateInternalDebtForm` stays unrouted (internal debts spec).
- Conventional Commits; no Co-Authored-By or Claude Session lines.
- `git push` is run by the user (`! git push`); Claude's shell hangs on SSH.
- Gates: `supabase test db`; `node scripts/pre-push.mjs` (lint `--max-warnings=0`, vitest, both tsc programs, Knip); `npm run build`; `npm run size` (378 KB budget); `npm run test:e2e:smoke`.
- Node 26 is not the shell default: prefix commands with `source ~/.nvm/nvm.sh && nvm use 26`. Read local Supabase URLs and keys from `supabase status -o env` (the local API is not on the default port).
- Re-run `npm run knip` after every change in Part B: config hints only appear once the report is otherwise empty.

```sql
-- Debts UI spec (docs/plans/2026-10-10-debts-ui-design.md), section 1: close the
-- cross-device gaps that become reachable once debts are creatable.

-- Gap 1: the server owns debts.updated_at. Inserts too: a debt created offline
-- must sort by arrival, or another device's catch-up mark skips it.
drop trigger if exists debts_set_updated_at on public.debts;
create trigger debts_set_updated_at
  before insert or update on public.debts
  for each row execute function update_updated_at_column();

drop trigger if exists internal_debts_set_updated_at on public.internal_debts;
create trigger internal_debts_set_updated_at
  before insert or update on public.internal_debts
  for each row execute function update_updated_at_column();

-- Catch-up pulls debt_payments on created_at; a late insert from an offline
-- device must sort by arrival too.
create or replace function public.set_created_at_now()
returns trigger
language plpgsql
set search_path = public
as $$
begin
  new.created_at := now();
  return new;
end
$$;

drop trigger if exists debt_payments_set_created_at on public.debt_payments;
create trigger debt_payments_set_created_at
  before insert on public.debt_payments
  for each row execute function public.set_created_at_now();

-- Gap 5: deleting a transaction keeps its ledger rows and clears their link.
-- Referential actions bypass RLS, so debt_payments stays append-only for clients.
alter table public.debt_payments alter column transaction_id drop not null;
alter table public.debt_payments drop constraint debt_payments_transaction_id_fkey;
alter table public.debt_payments
  add constraint debt_payments_transaction_id_fkey
  foreign key (transaction_id) references public.transactions(id) on delete set null;

-- Gap 2: a payment is reversed at most once, whichever device gets there first.
create unique index debt_payments_reverses_payment_id_unique
  on public.debt_payments (reverses_payment_id)
  where reverses_payment_id is not null;

-- Gap 4b: ids are the identity; a duplicate display name must not strand an
-- offline create and every payment queued behind it.
drop index if exists public.idx_debts_household_name_unique;
drop index if exists public.idx_internal_debts_household_name_unique;
```

```ts
/**
 * Post-pull ledger repair (debts UI spec, gap 2). Two devices can each reverse
 * one payment and add their own replacement. The unique reversal index stops the
 * duplicate reversal; this pass reverses whichever extra payments remain. Every
 * device picks the same keeper, so concurrent runs target the same rows, and the
 * index plus the processor's already-reversed rule absorb the overlap.
 */
import { db } from "@/lib/dexie/db";
import { reportError } from "@/lib/sentry";
import type { DebtPayment } from "@/types/debt";
import { DebtLedgerView } from "./ledgerView";
import { commitDebtWriteSet, mergeWriteSets, type DebtWriteSet } from "./outbox";
import { prepareReversal } from "./reversals";
import { updateMultipleDebtStatuses } from "./status";

export interface PulledDebtChanges {
  transactionIds: string[];
  paymentIds: string[];
}

function debtOf(payment: DebtPayment): string | undefined {
  return payment.debt_id ?? payment.internal_debt_id;
}

function isDefined<T>(value: T | undefined): value is T {
  return value !== undefined;
}

async function livePayments(rows: DebtPayment[]): Promise<DebtPayment[]> {
  const payments = rows.filter((row) => !row.is_reversal);
  if (payments.length === 0) return [];
  const reversals = await db.debtPayments
    .where("reverses_payment_id")
    .anyOf(payments.map((payment) => payment.id))
    .toArray();
  const reversed = new Set(reversals.map((reversal) => reversal.reverses_payment_id));
  return payments.filter((payment) => !reversed.has(payment.id));
}

async function outstandingEntityIds(): Promise<Set<string>> {
  const items = await db.syncQueue.where("status").anyOf("queued", "syncing").toArray();
  return new Set(items.map((item) => item.entity_id));
}

/** Live payments the transaction's current state does not account for. */
async function extrasForTransaction(
  transactionId: string,
  pending: Set<string>
): Promise<DebtPayment[]> {
  if (pending.has(transactionId)) return [];
  // Missing locally: not pulled yet (Dexie caches transactions on demand), or
  // deleted here, in which case the delete already reversed its payments.
  const transaction = await db.transactions.get(transactionId);
  if (!transaction) return [];
  const rows = await db.debtPayments.where("transaction_id").equals(transactionId).toArray();
  if (rows.some((row) => pending.has(row.id))) return [];

  const live = await livePayments(rows);
  const expectedDebt = transaction.debt_id ?? transaction.internal_debt_id;
  if (!expectedDebt) return live;

  const keeper = live
    .filter((p) => debtOf(p) === expectedDebt && p.amount_cents === transaction.amount_cents)
    .sort((a, b) => a.id.localeCompare(b.id))[0];
  if (!keeper) {
    if (live.length > 0) {
      reportError(new Error("Debt ledger does not match its transaction"), {
        subsystem: "debts",
        operation: "reconcile",
        extra: { transactionId, live: live.map((p) => p.id) },
      });
    }
    return [];
  }
  return live.filter((p) => p.id !== keeper.id);
}

/** A live payment pulled with a null link lost its transaction to a delete that raced an edit. */
async function orphans(pulled: DebtPayment[], pending: Set<string>): Promise<DebtPayment[]> {
  return livePayments(pulled.filter((row) => row.transaction_id === null && !pending.has(row.id)));
}

export async function reconcileDebtLedger(
  changes: PulledDebtChanges,
  userId: string
): Promise<{ reversedPaymentIds: string[] }> {
  const pending = await outstandingEntityIds();
  const pulled = (await db.debtPayments.bulkGet(changes.paymentIds)).filter(isDefined);
  const transactionIds = new Set([
    ...changes.transactionIds,
    ...pulled.flatMap((p) => (p.transaction_id ? [p.transaction_id] : [])),
  ]);

  const extras: DebtPayment[] = [];
  for (const transactionId of transactionIds) {
    extras.push(...(await extrasForTransaction(transactionId, pending)));
  }
  extras.push(...(await orphans(pulled, pending)));

  const view = new DebtLedgerView();
  const writeSets: DebtWriteSet[] = [];
  const reversed = new Set<string>();
  for (const payment of extras) {
    if (reversed.has(payment.id)) continue;
    reversed.add(payment.id);
    const { writeSet } = await prepareReversal(
      { payment_id: payment.id, reason: "reconcile" },
      userId,
      view
    );
    writeSets.push(writeSet);
  }
  if (writeSets.length > 0) await commitDebtWriteSet(mergeWriteSets(...writeSets));

  // Gap 4a: statuses follow the balance on every device, not just the payer's
  const touched = [...pulled, ...extras];
  const external = [...new Set(touched.flatMap((p) => (p.debt_id ? [p.debt_id] : [])))];
  const internal = [
    ...new Set(touched.flatMap((p) => (p.internal_debt_id ? [p.internal_debt_id] : []))),
  ];
  if (external.length > 0) await updateMultipleDebtStatuses(external, "external", userId);
  if (internal.length > 0) await updateMultipleDebtStatuses(internal, "internal", userId);

  return { reversedPaymentIds: [...reversed] };
}
```

```ts
/** Every external debt with its balance, for /debts. Reads Dexie, the debts source of truth. */
export function debtsListQueryOptions() {

  payments: DebtPayment[];
  deletion: { allowed: boolean; reason?: string };

/** One external debt for /debts/$debtId; null when this device has no such debt. */
export function debtDetailQueryOptions(debtId: string) {
  return queryOptions({
    queryKey: queryKeys.debts.detail(debtId),
    queryFn: async (): Promise<DebtDetail | null> => {
      const debt = await getDebt(debtId, "external");
      if (!debt || !isExternalDebt(debt)) return null;
      const [balance, payments, deletion] = await Promise.all([
        calculateDebtBalance(debtId, "external"),
        getDebtPayments(debtId, "external"),
        validateDebtDeletion(debtId, "external"),
      ]);
      return {
        debt,
        balance,
        payments,
        deletion: { allowed: deletion.valid, reason: deletion.errors[0] },
      };
    },
```

```tsx
import { useState } from "react";
import { useQuery, useQueryClient } from "@tanstack/react-query";
import { ArrowLeft } from "lucide-react";
import { toast } from "sonner";
import { Button } from "@/components/ui/button";
import { Dialog, DialogContent, DialogHeader, DialogTitle } from "@/components/ui/dialog";
import { LoadingSpinner } from "@/components/LoadingScreen";
import { PageShell } from "@/components/layout/PageShell";
import { diffCents } from "@/lib/currency";
import { confirm } from "@/lib/confirm";
import { archiveDebt, deleteDebt, unarchiveDebt } from "@/lib/debts/crud";
import { afterOutboxWrite } from "@/lib/offline/afterWrite";
import { reportError } from "@/lib/sentry";
import { debtDetailQueryOptions } from "@/lib/supabaseQueries";
import { useAuthStore } from "@/stores/authStore";
import { DebtBalanceDisplay } from "./DebtBalanceDisplay";
import { DebtProgressBar } from "./DebtProgressBar";
import { DebtStatusBadge } from "./DebtStatusBadge";
import { PaymentHistoryList } from "./PaymentHistoryList";
import { EditExternalDebtForm } from "./forms/EditExternalDebtForm";

interface DebtDetailPageProps {
  debtId: string;
  onBack: () => void;
  onRecordPayment: (debtId: string) => void;
  onDeleted: () => void;
}

export function DebtDetailPage({
  debtId,
  onBack,
  onRecordPayment,
  onDeleted,
}: DebtDetailPageProps) {
  const userId = useAuthStore((state) => state.user?.id);
  const queryClient = useQueryClient();
  const [isEditOpen, setIsEditOpen] = useState(false);
  const { data: detail, isLoading } = useQuery(debtDetailQueryOptions(debtId));

  const runWrite = async (
    operation: string,
    write: (uid: string) => Promise<void>,
    success: string
  ): Promise<boolean> => {
    if (!userId) {
      toast.error("Sign in to save debts");
      return false;
    }
    try {
      await write(userId);
      afterOutboxWrite(queryClient, userId, "debt");
      toast.success(success);
      return true;
    } catch (error) {
      reportError(error, { subsystem: "ui", operation });
      toast.error(
        error instanceof Error ? error.message : "Something went wrong. Please try again."
      );
      return false;
    }
  };

  if (isLoading) {
    return (
      <div className="flex items-center justify-center bg-background py-24">
        <LoadingSpinner size="large" className="text-primary" label="Loading debt" />
      </div>
    );
  }

  if (!detail) {
    return (
      <PageShell variant="centered">
        <div className="py-12 text-center">
          <p className="text-muted-foreground">Debt not found</p>
          <Button variant="outline" className="mt-4" onClick={onBack}>
            Back to debts
          </Button>
        </div>
      </PageShell>
    );
  }

  const { debt, balance, payments, deletion } = detail;
  const isArchived = debt.status === "archived";

  const handleDelete = async () => {
    const confirmed = await confirm({
      title: `Delete ${debt.name}?`,
      description: "It has no payments, so nothing else changes.",
      confirmLabel: "Delete",
      destructive: true,
    });
    if (!confirmed) return;
    const deleted = await runWrite(
      "delete-external-debt",
      (uid) => deleteDebt(debt.id, "external", uid),
      "Debt deleted"
    );
    if (deleted) onDeleted();
  };

  return (
    <PageShell variant="centered">
      <div className="space-y-6">
        <div className="flex items-center gap-4">
          <Button variant="ghost" size="sm" aria-label="Back to debts" onClick={onBack}>
            <ArrowLeft className="h-4 w-4" />
          </Button>
          <h1 className="flex-1 text-xl font-bold">{debt.name}</h1>
          <DebtStatusBadge status={debt.status} />
        </div>

        <div className="space-y-4 rounded-lg border bg-card p-6">
          <div data-testid="debt-balance">
            <DebtBalanceDisplay
              balance={balance}
              originalAmount={debt.original_amount_cents}
              showPercentage
            />
          </div>
          <DebtProgressBar
            paid={diffCents(debt.original_amount_cents, balance)}
            total={debt.original_amount_cents}
          />
          <div className="flex flex-wrap gap-2">
            {!isArchived && (
              <Button onClick={() => onRecordPayment(debt.id)}>Record payment</Button>
            )}
            <Button variant="outline" onClick={() => setIsEditOpen(true)}>
              Edit
            </Button>
            {isArchived ? (
              <Button
                variant="outline"
                onClick={() =>
                  void runWrite(
                    "unarchive-external-debt",
                    (uid) => unarchiveDebt(debt.id, "external", uid),
                    "Debt unarchived"
                  )
                }
              >
                Unarchive
              </Button>
            ) : (
              <Button
                variant="outline"
                onClick={() =>
                  void runWrite(
                    "archive-external-debt",
                    (uid) => archiveDebt(debt.id, "external", uid),
                    "Debt archived"
                  )
                }
              >
                Archive
              </Button>
            )}
            {payments.length === 0 && (
              <Button
                variant="destructive"
                disabled={!deletion.allowed}
                onClick={() => void handleDelete()}
              >
                Delete
              </Button>
            )}
          </div>
          {payments.length === 0 && !deletion.allowed && deletion.reason && (
            <p className="text-sm text-muted-foreground">{deletion.reason}</p>
          )}
        </div>

        <PaymentHistoryList payments={payments} />
      </div>

      <Dialog open={isEditOpen} onOpenChange={setIsEditOpen}>
        <DialogContent>
          <DialogHeader>
            <DialogTitle>Edit debt</DialogTitle>
          </DialogHeader>
          <EditExternalDebtForm
            debt={debt}
            onSuccess={() => setIsEditOpen(false)}
            onCancel={() => setIsEditOpen(false)}
            onArchive={() => setIsEditOpen(false)}
          />
        </DialogContent>
      </Dialog>
    </PageShell>
  );
}
```

## Decisions & Deferrals

Planning (2026-10-10), recommended defaults applied; each supersedes the spec text it names (the spec is updated to match):

- **Server-set `created_at` on `debt_payments` inserts and `updated_at` on debt inserts (added).** Why: catch-up advances one shared cursor and pulls payments on `created_at`; a payment pushed late from an offline device sorts below another device's mark and never reaches it, so reconcile could never converge. Revisit: transactions keep client insert timestamps (pre-existing deferral) until catch-up gaps are reported.
- **Keeper is the matching live payment with the smallest `id` (spec said newest by `created_at`).** Why: a device keeps its own rows' client `created_at` while others hold the server's, so "newest" differs per device.
- **Local ledger rows keep their `transaction_id` after a transaction delete (spec said null them).** Why: modifying existing ledger rows without queue items breaks the outbox invariant test; the server's SET NULL keeps the server correct. Cost: the deleting device's history shows the old transaction reference instead of "Transaction deleted".
- **Reconcile skips transactions missing from Dexie and reverses pulled orphans (null link).** Why: Dexie caches transactions on demand, so absence does not prove a delete; a null link only comes from the server's SET NULL, which only leaves a live payment behind when a delete raced an edit.
- **No-match is reported only when live payments exist.** Why: a linked transaction with no live payment yet is usually a payment not pulled yet; reporting it would be noise.
- **Debts routes follow `/analytics` (layout route + `index.tsx`), not `/accounts`.** Found: `accounts.tsx` renders no `<Outlet />`, so `/accounts/$accountId` (linked from the mobile `AccountBalanceCard`) never shows its page. Out of scope here. Revisit: Decisions Needed 2.
- **Page bodies live in `DebtsPage`/`DebtDetailPage`; route files only wire navigation and the payment dialog.** Why: testable without file-route plumbing; `TransactionFormDialog` needs a router for `useBlocker`.
- **The three `tests/e2e/debts/*.spec.ts` files are deleted.** Why: they target `/debts/demo`, which never existed; all 24 tests skip or fail in the 2026-10-02 baseline. Replaced by `tests/e2e/debts.spec.ts` in smoke.
- **Reconcile staleness guard (user decision 2026-10-10, from the Task 3 review).** Reconcile skips a transaction when any live payment's `created_at` is later than the transaction's `updated_at` (compared as dates): another device's payment synced while its transaction update is still retrying, so the transaction row is stale and reversing against it would strand the ledger. To make the guard sound, a transaction edit now queues its debt items before the transaction update (as the delete path already does), so a completed edit always leaves the transaction newer than its own payments. The guard can only suppress reversals. If a payment's push is retried and lands after its own transaction update, every other device skips that transaction; the originating device heals it, because catch-up never overwrites an existing `debt_payments` row (`mergeRecord`, insert-only tables), so its own payment keeps the local edit-time `created_at`, which is earlier than the pulled transaction's server `updated_at` (Task 3 re-review; relies on the editing device's clock not running ahead of the server). Rejected: deferring (balance stays wrong); ordering the processor by parent (larger deferred processor change).
- **Delete-time reversals are stored unlinked (added in execution, Task 5b, 2026-10-10).** Why: Task 1 review found that once the server accepts the delete, a reversal pushed after it fails with FK 23503. Cross-device, an edit made on another device after the delete used to fail the same way; since 914bd37 the processor retries those inserts unlinked, so they land and reconcile's orphan rule reverses the live payment (the stale-transaction display stays part of the edit/delete race deferred below).
- **Not handled (deferred):** an edit/delete race leaves the editing device showing the deleted transaction, because hard deletes do not propagate through catch-up (no tombstones; realtime is inert in production). Revisit: when deletes need to propagate across devices. Also: the device that drops a losing reversal shows a stale balance until its next pull (one autoSync cycle).
- **Keeper comparison is by code unit, not `localeCompare` (final review, fixed `fix(debts): pick the reconcile keeper by code-unit order`).** Why: under `da-DK`/`nb-NO` "aa" sorts after "ab", so devices in different locales would pick different keepers and reverse each other's.
- **A debt payment create that fails FK 23503 on `debt_payments_transaction_id_fkey` retries once with `transaction_id: null` and nulls the local row's link (final review Important 2, fixed `fix(sync): retry an orphaned debt payment without its transaction link`).** Why: when a transaction delete lands before a retried linked reversal or payment, SET NULL has already cleared the link on the server; the retry reproduces that outcome instead of stranding a balance. The local row is nulled so a later reconcile treats a live payment as an orphan, matching the server. Narrow exception to "local rows keep their link". The general processor ordering fix stays deferred.
- **D1: reconcile's reads and commit are not one Dexie transaction.** Why: a user edit in the window can create a second local reversal; the server rejects it with 23505 and the processor rule drops it. Revisit: if duplicate-reversal drops show up in Sentry.
- **D2: `failed` outbox items are not in reconcile's pending skip set.** Why: both partial-failure shapes were walked and cause no server double count; local divergence is the existing Sync Issue class. Revisit: with Sync Issue resolution UX.
- **D3: keeper can diverge under client clock skew.** Why: transactions are last-write-wins on a client `updated_at`, so a device with a fast clock keeps its own version and picks a different keeper, reversing both. Pre-existing LWW issue that reconcile now acts on. Revisit: server-authoritative transaction stamps or Phase B clocks.
- **D4: `check_payment_count_limit` (100 rows per debt) counts reversals, and its P0001 is retried before failing.** Why: each amount edit costs 2 rows and reconcile adds more; reachable once the UI exists. Revisit: a `debts-ui` task before the E2E task (exclude reversals from the count or make the message non-retryable).
- **D5: the no-match `reportError` repeats on every pull touching the transaction; a linked transaction with zero live payments is silent.** Why: noise only, no data effect. Revisit: when Sentry volume matters.
- **D6: never-edited linked transactions are always skipped by the staleness guard.** Why: harmless, a never-edited transaction cannot have an extra payment. Revisit: add a one-line comment in `reconcile.ts` when next touched.
- **D7: `cancelUnsentCreate` leaves the debt's create row in `db.events`, and `findUnsentDebtCreate` runs outside the transaction.** Why: audit-only, single UI thread; readers of `db.events` unchecked. Revisit: when events are consumed for display.
- **D8: the processor's 23505 rule deletes by `payload.id` without cleaning other queue items for that id, and its tests do not assert the insert call.** Why: reversals never get follow-up items. Revisit: if reversals ever gain follow-up queue items.
- **D9: catch-up records ids for rows rejected by validation, post-reconcile invalidation is untested, and reconcile-written items wait for the next `processQueue`.** Why: reconcile tolerates missing rows and the next autoSync trigger pushes the items. Revisit: with the `debts-ui` query invalidation work.
- **D10: the integration test calls reconcile explicitly because it has no auth-store user.** Why: the wiring is covered by `realtime.test.ts`. Revisit: if the test gains an auth-store user.
